## C1. Spacing · Grid

**원칙 설계**
- [ ] 스페이싱 스케일의 근거 — 기준 단위(4px? 8px?)와 스텝 구성
- [ ] Grid 체계 — 컬럼 수, 거터, 마진
- [ ] 컴포넌트 내부 간격(B4)과 화면 간격의 책임 경계 ⚠️
      → 같은 값을 두 곳에서 관리하지 않도록 어느 쪽이 원본인지 정해야 함

**네이밍 규칙**
- [ ] [A3 Responsive 토큰](../A-token/A3-semantic-responsive.md)의 `Target/Role/Variant`로 전부 표현되는가
- [ ] Grid 관련 값의 토큰 이름

**사용 규칙**
- [ ] 어떤 간격에 어떤 Role을 쓰는가 (Container / Section / Page …)
- [ ] 스케일 밖 수치 사용 금지 — 예외 조건
- [ ] Grid를 벗어나는 배치(full-bleed 등)의 허용 조건

**확장 규칙 / 판별 테스트 / 코드 동기화**
- [ ] 새 스텝 추가 기준
- [ ] 판별 질문 세트 (예: "이 gap 값이 토큰에 바인딩되어 있는가?" → 아니면 `DENY-02` 확장 대상)
- [ ] CSS 변수 / 레이아웃 유틸리티와의 대응

## C2. Breakpoint · Responsive

**원칙 설계 — 🟡**
- [x] Responsive를 별도 Semantic 컬렉션으로 분리 운용한다는 결정
- [ ] ⚠️ **Breakpoint 목록과 각각의 정의** — 없으면 A3의 Mode 축이 정해지지 않음
- [ ] Breakpoint 기준 — 뷰포트 폭인가 컨테이너 폭인가
- [ ] 플랫폼 범위 — Web만인가, 앱도 포함인가

**네이밍 규칙**
- [ ] Breakpoint 이름 (SM/MD/LG? Mobile/Tablet/Desktop?)
- [ ] A3 컬렉션의 Mode 이름과 일치시킬 것

**사용 규칙**
- [ ] 어떤 속성이 Breakpoint에 따라 변하는가 / 변하지 않는가
- [ ] Breakpoint 사이 값의 처리 (fluid vs stepped)
- [ ] 컴포넌트 단위 반응형과 화면 단위 반응형의 경계

**확장 규칙 / 판별 테스트 / 코드 동기화**
- [ ] Breakpoint 추가 시 A3 전체 파급 확인 절차 ⚠️ (영향 범위가 큼)
- [ ] 판별 질문 세트
- [ ] 미디어쿼리 / 컨테이너 쿼리 중 무엇으로 구현하는가

## C3. 화면 구조 · 템플릿

> AI가 새 화면을 생성할 때 참조할 구조 원본. 이것이 없으면 AI는 매번 새 구조를 발명한다.

**원칙 설계**
- [ ] 화면 구성 단위 정의 — Page / Section / Region
- [ ] 표준 템플릿 목록 (List / Detail / Form / Dashboard …)
- [ ] 템플릿을 컴포넌트로 만들 것인가, 규칙 문서로 둘 것인가

**네이밍 규칙**
- [ ] 구조 단위의 역할 어휘 (→ [D1 Frame Naming](../D-naming/README.md)과 **단일본 공유** ⚠️)

**사용 규칙 / 확장 규칙 / 판별 테스트 / 코드 동기화**
- [ ] 어떤 화면에 어떤 템플릿을 쓰는가
- [ ] 템플릿을 벗어나야 할 때의 절차
- [ ] 판별 질문 세트 (예: "이 화면의 최상위 구조가 정의된 템플릿 중 하나인가?")
- [ ] 라우팅·레이아웃 컴포넌트와의 대응
