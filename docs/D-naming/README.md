## D1. 프레임 · 레이어 네이밍

**원칙 설계**
- [ ] 이름으로 무엇을 표현하는가 — **역할**인가, 내용인가, 둘 다인가
- [ ] 어느 깊이까지 이름을 강제하는가 (최상위 프레임만? 모든 레이어?)
- [ ] Auto Layout 구조로 이미 드러나는 정보를 이름에도 **중복 표기할 것인가** ⚠️
- [ ] 역할이 없는 순수 장식 프레임의 처리

**네이밍 규칙**
- [ ] ⚠️ **역할 어휘의 닫힌 집합** — Header / Nav / Content / Aside / Footer / Item / Group …
      → C3 화면 구조 단위와 **같은 어휘를 써야 함**. 단일본 위치 결정 필요
- [ ] 세그먼트 문법과 구분자
- [ ] 표기 규칙 — A 토큰과 통일할 것인가 (띄어쓰기 + `/`)
- [ ] 인덱스·번호 허용 여부

**사용 규칙**
- [ ] ⚠️ **기본 이름 금지** — `Frame 48095626`, `Rectangle 12341239` 류를 위반으로 판정
      *(Figma 포럼에서 확인된 실제 사례)*
- [ ] 이름 중복 허용 범위
- [ ] 영문/한글 정책

**확장 규칙 / 판별 테스트 / 코드 동기화**
- [ ] 새 역할 어휘 추가 절차
- [ ] 판별 질문 세트

```
Q1. 이름이 Figma 기본 생성 패턴(`Frame \d+`, `Rectangle \d+` …)과 일치하는가? → 위반
Q2. 첫 세그먼트가 정의된 역할 어휘 집합 안에 있는가?
Q3. 표기 규칙(구분자·대소문자)을 따르는가?
```

- [ ] 코드의 DOM 구조 / 시맨틱 태그와의 대응

## D2. 컴포넌트 · 에셋 네이밍

> **A4 Component Token의 첫 세그먼트가 참조하는 기준 집합이 여기서 나옵니다.**

**원칙 설계**
- [ ] 컴포넌트 이름이 표현할 것 — 층(B1) / 역할 / 둘 다
- [ ] 아이콘·이미지 등 에셋도 같은 규칙을 쓰는가
- [ ] **정본(single source) 위치** — 컴포넌트 이름 목록이 어디에 존재하는가 ⚠️

**네이밍 규칙**
- [ ] 문법과 구분자
- [ ] A4 Component Token의 `Component` 슬롯과 **문자열 수준으로 일치**시킬 것인가
- [ ] 코드 컴포넌트 이름과의 관계 (동일? 변환 규칙?)
- [ ] 아이콘 네이밍 (기능 기준 vs 형태 기준)

**사용 규칙 / 확장 규칙 / 판별 테스트 / 코드 동기화**
- [ ] 이름 변경 시 절차 — 토큰·Code Connect 파급 확인
- [ ] 신규 컴포넌트 등록 절차 (`DENY-03`의 정당한 경로)
- [ ] 판별 질문 세트 (예: "이 컴포넌트 이름이 기준 집합에 등록되어 있는가?")
- [ ] 코드 컴포넌트 목록과의 동기화 방법
