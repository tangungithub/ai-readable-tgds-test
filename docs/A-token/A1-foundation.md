## 1. 원칙 설계 — 🟡

- [x] 존재 이유: 원시 값을 스케일 단위로 보관하고, 상위 티어가 참조할 단일 출처가 된다
- [x] 계층 확정: **2단** (`Scale/Step`), **비색상 포함 전부** 동일하게 2단
- [x] 참조 방향: Foundation은 아무것도 참조하지 않는다 (최하위)
- [ ] **책임 경계 명문화** — Foundation에 의미를 담지 않는다는 원칙이 문서에 문장으로 없음
- [ ] **스케일 설계 근거** — 왜 이 Step 개수인가 (색상 100~900, 스페이싱 스텝 등)의 근거 부재
- [ ] Foundation에 들어갈 수 있는 **속성 종류의 전체 목록** — Color / Dimension / Font Family / Font Weight / Duration / Easing / Shadow … 어디까지가 Foundation인가

## 2. 네이밍 규칙 — ✅

- [x] 문법: `Scale/Step`
- [x] 표기: Figma는 띄어쓰기 단어 구분 (`Font Family/Gmarket Sans`)
- [x] 전 속성 2단 통일 — 비색상도 예외 없음
- [x] 구분자: `/`

> Foundation은 Step이 수치 스케일이라 enum이 자연히 닫힙니다. 상위 티어와 달리 이 축은 완료로 봅니다.

## 3. 사용 규칙 — 🟡

- [x] 금지: Foundation을 **컴포넌트에 직접 바인딩하지 않는다** (반드시 Semantic 경유)
- [ ] **예외 조건** — Foundation 직접 참조가 허용되는 경우가 있는가? 있다면 어떤 경우인가
- [ ] Do / Don't 예시
- [ ] 유사 값 중 선택 기준 — `Red/300` vs `Red/400` 같은 인접 Step 선택 근거

## 4. 확장 규칙 — 🟡

- [x] 원칙 문서에 확장 체크리스트 개념은 존재
- [ ] **새 Scale 추가 기준** — 어떤 조건이면 새 색상 Scale을 여는가
- [ ] **새 Step 추가 기준** — 스케일 중간값을 끼워 넣는 것을 허용하는가
- [ ] 승인자 지정
- [ ] 폐기 절차

## 5. 판별 테스트 — 🟡

- [x] 원칙 문서에 판별 테스트가 존재 (단, **3장·7장에 중복** → 단일본 필요)
- [ ] 중복 해소 후 단일본 확정
- [ ] 규칙 ID 부여
- [ ] 아래 질문 세트 확정

```
Q1. 세그먼트가 정확히 2단인가?
Q2. Step 값이 정의된 스케일 위의 값인가?
Q3. 이 토큰이 다른 토큰을 참조하고 있는가? (참조하면 위반 — Foundation은 최하위)
Q4. 이 토큰이 컴포넌트에 직접 바인딩되어 있는가? (되어 있으면 위반)
Q5. 이름에 의미·역할 단어가 들어 있는가? (들어 있으면 위반 — Foundation은 의미를 담지 않음)
```
