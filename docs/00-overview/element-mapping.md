# AI Readable 5요소 ↔ 원칙 영역 매핑

리더십 소개 세션에서는 AI Readable을 **5가지 요소**로 설명합니다.
그러나 이 중 Auto Layout·Slot·Code Connect는 **Figma의 기능**이지 디자인 시스템 원칙이 아닙니다.

이 저장소는 **원칙**을 축으로 구성하고, 5요소는 각 원칙을 **구현하는 수단**으로 배치합니다.
발표 자료와 구축 실무를 같은 지도 위에서 보기 위한 대조표입니다.

---

## 대조표

| 소개 세션의 요소 | 실제 정체 | 이 저장소에서의 위치 |
|---|---|---|
| **Variable** | 토큰 체계를 담는 Figma 기능 | [A. Token 체계](../A-token/) 전체 |
| **Frame Naming** | 레이어 식별 규칙 | [D. 식별·메타데이터](../D-naming/) — D1 |
| **Auto Layout** | 레이아웃 Figma 기능 | [B. Component](../B-component/) B4 구조·조합 규칙의 **구현 수단** + [C. Layout](../C-layout/) C1·C2 |
| **Slot** | 변형 수용 패턴 | [B. Component](../B-component/) B5 유연성·변형 수용의 **구현 수단** |
| **Code Connect** | 매핑 Figma 기능 | [E. Design–Code 연결](../E-design-code/) — E1 |

---

## 왜 축을 바꿨는가

**원칙과 수단을 같은 층에 두면 빈칸이 무엇을 뜻하는지 알 수 없습니다.**

- "Auto Layout ⬜"은 *무엇을* 안 했다는 뜻인가? 적용을 안 한 것인가, 적용 기준을 안 정한 것인가, 간격 값을 토큰에 안 묶은 것인가?
- 반대로 "C1 Spacing·Grid — 사용 규칙 ⬜"은 **정확히 무엇이 없는지**를 가리킵니다.

또한 원칙 축은 도구에 종속되지 않습니다. Figma가 아닌 도구로 옮기거나, Figma가 기능을 바꿔도 원칙 목록은 그대로 유효합니다. 대시보드가 도구의 기능 목록이 되면 도구가 바뀔 때 대시보드를 다시 만들어야 합니다.

---

## 발표에서는 그대로 5요소를 씁니다

리더십 대상 세션에서 "B5 유연성·변형 수용 원칙"이라고 말할 이유는 없습니다.
**설명은 5요소로, 구축은 원칙 영역으로.** 이 문서가 두 언어 사이의 사전 역할을 합니다.
