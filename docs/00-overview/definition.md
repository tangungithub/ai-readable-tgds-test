# AI Readable — 정의와 목표

## 정의

> **AI Readable** = 추가 설명 문서 없이, **구조 자체만으로** AI가 의도를 오류 없이 해석할 수 있는 상태

## 목표

1. **더 적은 추가 컨텍스트로도 할루시네이션 없이 작동**한다
2. 컨텍스트가 필요하더라도 **'설명·파싱 원리'는 최소화**한다 — 구조가 스스로 말하게 한다

> 핵심 역설: 문서를 더 쓰는 것이 아니라, **문서가 덜 필요한 구조**를 만드는 일입니다.

---

## 문제 정의

| | |
|---|---|
| **문제** | 디자인 시스템은 만들 때가 아니라 **유지할 때** 무너진다. 서비스 확장 속도 ∝ 일관성 붕괴 속도 |
| **원인** | 플랫폼별 코드베이스 간 연결 단절 + 디자인–코드 괴리. **시각적 일관성 O · 일관성의 지속성 X** |
| **전환** | 병목은 AI의 능력이 아니라, **AI가 우리 시스템을 읽을 수 없다**는 것 |

---

## AI Readable은 별도의 작업이 아니다

이 저장소가 "AI Readable 체크리스트"가 아니라 **"디자인 시스템 원칙의 구현 체크리스트"**인 이유입니다.

AI Readable은 디자인 시스템 위에 얹는 추가 레이어가 아니라, **원칙이 제대로 구현된 상태의 다른 이름**입니다.

| 사람에게 필요한 것 | AI에게 필요한 것 |
|---|---|
| 이 토큰을 언제 쓰는지 알기 | 이 토큰을 언제 쓰는지 **판정 가능한 형태로** 적혀 있기 |
| 컴포넌트 변형 범위를 짐작하기 | 변형 범위가 **enum으로 닫혀** 있기 |
| 이름을 보고 역할을 이해하기 | 이름이 **닫힌 역할 어휘**를 따르기 |

차이는 **"이해 가능"과 "판정 가능"** 사이에 있습니다.
사람은 애매한 규칙도 맥락으로 메우지만, AI는 메우는 대신 **그럴듯하게 지어냅니다.**

그래서 이 대시보드의 **판별 테스트 축**이 곧 AI Readable 여부의 척도입니다.

## 기대 효과

- **비용** — 온보딩 시간 단축. 사람도 AI도 시스템을 새로 익히는 시간이 줄어든다
- **품질** — 일관성의 강제. 개발자와 AI 모두에게 동일한 게이트웨이가 적용된다
- **속도** — 문제 해결 가속. 프로젝트 장기화·서비스 확장 국면에서 시스템을 이해하는 AI가 더 빠르게 해결한다
- **지표** — AI의 기계적 디자인 초안 생성 = 디자인 시스템 활용 지표. **"사람보다 시스템을 잘 쓰는 에이전트"**

## 왜 지금인가

GitClear의 2026년 분석(6.23억 건의 코드 변경)에서 **중복 코드 블록이 81% 증가**하고 **리팩터링 비율이 21%에서 3.8%로 떨어졌습니다.** 복사·붙여넣기가 재사용을 추월했습니다.

> AI는 읽히지 않는 시스템 위에서 **비일관성의 가속기**로 작동합니다.
> 시스템을 읽히게 만드는 일은 AI 도입의 후속 과제가 아니라 **전제 조건**입니다.
