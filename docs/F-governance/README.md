## F1. 판별 테스트 통합본

> A~E 각 단위에 흩어진 판별 질문을 한 곳으로 모은 **규칙 원본**.

**원칙 설계**
- [ ] ⚠️ **단일본 위치 결정** — 각 문서에 두고 여기서 인덱스만 할 것인가, 여기로 모을 것인가
- [ ] 현재 원칙 문서 3장·7장의 **중복 해소** (어느 쪽이 원본인가)
- [ ] 규칙의 등급 — Deny / Warn / Info를 둘 것인가

**네이밍 규칙**

- [ ] ID 부여·재사용 정책 (폐기된 ID를 재사용하는가)

**사용 규칙 / 확장 규칙 / 코드 동기화**

## F2. 게이트웨이 Deny 규칙

**원칙 설계 — 🟡**
- [x] Deny 3종 확정
- [x] 사람과 AI에게 **동일하게** 적용한다
- [ ] 적용 지점 — 디자인 단계인가, 커밋인가, 빌드인가, 전부인가
- [ ] Warn 등급 도입 여부 — 즉시 차단하기엔 이른 규칙의 처리
- [ ] 레거시 소급 적용 여부

**네이밍 규칙 — 🟡**
- [x] `DENY-NN` 형식
- [ ] F1 규칙 ID 체계와의 통합

### 확정된 Deny 규칙

| ID | 위반 | 전제 조건 (없으면 판정 불가) |
|---|---|---|
| `DENY-01` | DS에 없는 Component Name을 사용한 신규 토큰 | 토큰 측 판정 ✅ — [A4](../A-token/A4-component-token.md) 인덱스 등록제 `CMP-A5` + `CMP-L06`. 남은 전제: [D2](../D-naming/README.md) Figma 컴포넌트 이름 ↔ 인덱스 일치 규칙 |
| `DENY-02` | 토큰을 거치지 않은 RAW 색상 사용 | 판정 규칙 ✅ — `CMP-L02`·`SEM-L11`. 남은 전제: [A2](../A-token/A2-semantic-theme.md) 등록부(`token/Semantic-theme.json`) + 허용 예외 목록 |
| `DENY-03` | DS 프로젝트 외부에서 신규 컴포넌트를 제작한 커밋 | [D3](../D-naming/README.md) DS 프로젝트 **경계 정의** |

> ⚠️ `DENY-01`·`DENY-02`는 토큰 측 판정 규칙이 생겼지만 판정 **대상**(등록부·Figma 이름 집합)이, `DENY-03`은 경계 정의가 비어 있습니다. 게이트웨이를 먼저 만들 수 없는 이유입니다.

**사용 규칙 / 확장 규칙 / 코드 동기화**
- [ ] **예외 승인 절차** — Deny를 의도적으로 통과시켜야 할 때 누가 어떻게 승인하는가
- [ ] 검출 실패(false negative) 발견 시 처리
- [ ] 오탐(false positive) 신고 경로
- [ ] 새 Deny 규칙 추가 기준 — 어떤 조건을 만족해야 Warn에서 Deny로 승격하는가
- [ ] CI 파이프라인 편입 방식
