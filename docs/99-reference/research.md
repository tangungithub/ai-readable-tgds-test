# 근거 리서치

"모범 사례가 없으면 무엇이 그 자리를 대신하는가"에 대한 1차 출처 확인 결과입니다.
발표·문서에서 인용할 때는 **아래 검증된 항목만** 사용합니다.

## 검증된 근거 (1차 출처 확인 완료)

### 벤더가 직접 이름 붙인 안티패턴
- **Figma Check designs**가 *hard-coded color / dimension / typography 값 + detached component*를 공식 감지 대상으로 명문화
  → 안티패턴에 벤더가 직접 이름을 붙였다는 점에서 가장 강한 근거
- **Figma의 detach 정의**: "연결만 끊고 레이어·속성은 그대로 남긴다"
  → 겉모습이 멀쩡해서 아무도 눈치채지 못한다. **"오늘의 일관성 / 내일의 일관성"** 논지의 핵심

| Deliveroo | 최다 detach 컴포넌트 8개 중 **7개가 multi-line text 포함** → detach는 유연성 결핍 신호 | B5 |

## ⛔ 절대 쓰면 안 되는 것

| 자주 인용되는 것 | 왜 안 되는가 |
|---|---|
| "Google 41가지 파란색" | A/B 테스트 일화지 디자인 부채 사례가 아님. 한국 키노트에서 자주 오용됨 |
| "Airbnb/Spotify/GitHub 수백 가지 회색", "Facebook 색상 261개" | 1차 출처 없음 |
| "디자인→코드 핸드오프 재작업률 N%" 류 | 검증 가능한 1차 연구가 존재하지 않음 (전부 벤더 SEO 콘텐츠) |
| "Figma Design Systems Report" | **그런 연간 보고서 자체가 없음.** DS 연간 리포트는 zeroheight가 유일 (Sparkbox는 2022년판이 마지막) |
| "Auto Layout 사용률 N%", "detach율 N% 이상 위험" | 그런 공식 수치·임계값 없음 |
| DejaVu "JS 94% 중복" | 중복의 70%가 node_modules 커밋 탓. UI 복붙 증거 아님 |

> ⚠️ 마지막 항목은 [F5 활용 지표](../F-governance/README.md)에 직접 영향을 줍니다.
> **외부 벤치마크가 존재하지 않으므로 목표치는 자체 기준선(baseline)으로 잡아야 합니다.**
